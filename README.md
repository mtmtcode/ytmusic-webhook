# YouTube Music Webhook

YouTube Musicの曲変更を検知して、任意のHTTP(S) URLへJSONをPOSTするChrome拡張です。**送信先ごとにJSONテンプレートと認証を設定でき、LaMetric TIMEをプリセットとして用意しています。** ラズパイ上の受信ツールとLaMetricに、異なる形式で直接送信できます。

Manifest V3 / JavaScript / ビルド不要 / 外部依存なし。Chrome 120以降が必要です。

## 導入

1. ZIPを展開し、Chromeで `chrome://extensions` を開きます。
2. デベロッパーモードをONにします。
3. 「パッケージ化されていない拡張機能を読み込む」で `manifest.json` のあるフォルダーを選びます。
4. 拡張アイコンから設定を開きます。
5. 既に開いていたYouTube Musicのタブを再読み込みします。

既存の1.x版を更新する場合は、同じフォルダーのファイルを置き換えて拡張を再読み込みしてください。旧設定のホスト・APIキー・ON/OFFをLaMetric送信先へ自動移行します。旧ループ回数はJSONの数値に変換し、通知IDなどの削除用状態は破棄します。2.x版の `{{cycles}}` も保存済みの設定値でJSONに埋め込みます。処理途中だった旧バージョンの曲は再送せず、Content Scriptが次に報告した実際の曲から再開します。YouTube Musicのタブも再読み込みしてください。旧バージョンと同じフォルダーを使うことで拡張のIDを維持してください。

3.1版では `{{text}}` を廃止しました。既存の標準LaMetricテンプレートは2フレームへ自動移行し、カスタムテンプレート内の `{{text}}` は `{{title}} / {{artist}}` に置換します。URL・認証とJSONのその他の指定は維持します。

## 送信先の設定

「＋ Webhook」「＋ LaMetric」から追加します。最大20件登録でき、全体の通知ON/OFFと送信先ごとのON/OFFがあります。追加・変更・削除は「すべて保存」で反映されます。保存時には最新の観測済みの曲が、有効な送信先へ送信されます。

各送信先に次を設定できます。

| 設定 | 内容 |
| --- | --- |
| 名前 | 設定画面で識別する名前 |
| プリセット | 汎用Webhook / LaMetric TIME。切替時にURL・認証・テンプレートなどを初期値に戻します |
| POST先URL | HTTP(S)の完全なURL。パス・ポート・クエリも指定可能 |
| 認証 | なし / Basic / Bearerトークン |
| JSONテンプレート | その送信先へPOSTするJSONの構造 |

URL内の認証情報、フラグメント、空白、ワイルドカード、HTTP(S)以外のスキームは受け付けません。URLの変数展開はありません。Basic認証のユーザー名にはコロンを使用できません。カスタムヘッダー・任意スクリプト・任意HTTPメソッドの設定には対応していません。

保存・接続テスト時、入力したホストだけへのHTTP(S)接続権限を要求します。未許可の場合は保存・送信しません。Chromeの権限はパスやポートで限定できませんが、実際の通信には設定したURLを使用し、リダイレクトは追従しません。削除済みの送信先の権限は自動では取り消しません。

### 汎用Webhook：ラズパイの例

送信先： `http://raspberrypi.local:3000/now-playing`

```json
{
  "event": "track_changed",
  "track": {
    "title": "{{title}}",
    "artist": "{{artist}}"
  },
  "source": "{{source}}"
}
```

曲名が `Song`、アーティストが `Artist` の場合、次がPOSTされます。

```json
{
  "event": "track_changed",
  "track": {
    "title": "Song",
    "artist": "Artist"
  },
  "source": "youtube-music"
}
```

受信側はJSONを受け付けるHTTPサーバーを別途用意してください。汎用Webhookではすべての2xx応答を成功として扱い、204や空の応答も利用できます。通知IDの取得やDELETEは行いません。

### LaMetric TIMEプリセット

- URL： `http://端末のホストまたはIP:8080/api/v2/device/notifications`
- 認証：Basic、ユーザー名 `dev`（固定）、パスワードにローカルDevice APIのAPIキー
- HTTPポート8080、APIパスは固定です。ホスト部分を自分の端末に変更してください。
- PCから端末に接続できるLANで使用してください。

初期JSON：

```json
{
  "priority": "info",
  "model": {
    "cycles": 1,
    "frames": [
      { "text": "{{title}}" },
      { "text": "{{artist}}" }
    ]
  }
}
```

曲名とアーティスト名をそれぞれ別のフレームで表示します。このテンプレートも自由に編集できます。ループ回数はJSON内の `"cycles": 1` を直接変更してください。0は永続表示です。ループ回数の専用設定欄やテンプレート変数はありません。

LaMetricも曲変更時にPOSTするだけで、前回通知のDELETEや通知IDの取得・保存は行いません。送信先の変更・削除、OFF切替時にも端末上の通知には操作を加えません。既存の通知が残るかどうかはLaMetric側の表示動作とテンプレートの指定によります。永続表示を指定した場合も拡張から自動削除しません。

### テンプレート変数

| 変数 | 値 |
| --- | --- |
| `{{title}}` | 曲名 |
| `{{artist}}` | アーティスト名 |
| `{{source}}` | `youtube-music` |

JSONの文字列値内に記述します。例えば `"message": "再生中：{{title}} / {{artist}}"` のような文章中の置換も可能です。数値・真偽値・配列などの固定値はJSONに直接記述してください。

JSONを解析した後に値を展開してからJSONとしてシリアライズするため、曲名の引用符・バックスラッシュ・改行でJSONが壊れません。曲名の中にある `{{artist}}` などを再解釈することもありません。未対応の変数、JSON構文エラー、キーでの変数使用、64KB超のテンプレート、深すぎる入れ子は保存時に拒否します。テンプレートにはJavaScriptや式評価の機能はありません。

「サンプル曲で送信JSONを確認」で、実際の送信形式を通信なしで確認できます。

## 接続テスト

- **汎用Webhook**：入力中のテンプレートでサンプル曲 `接続テスト / YouTube Music` を実際にPOSTします。受信側の処理が実行されます。
- **LaMetric**：認証付き `GET /api/v2/device/notifications` を実行します。接続と認証のテストで、通知は作成しません。

接続テストは入力中の設定を使い、設定を保存しません。通知全体や送信先がOFFでも、テストボタンからの通信は実行します。LaMetricのJSONが実機で表示できるかは、保存後の実曲送信で確認してください。

## 動作と状態管理

- Content Scriptが `music.youtube.com` のプレイヤーバーをMutationObserverで監視します。曲名とbylineの先頭アーティストリンクが揃い、約500ms間隔の2回の確認で安定したら送信します。DOM変更の連発でタイマーが無期限に延期されないようにしています。
- SPA遷移、プレイヤーバーのDOM再生成、通常のバックグラウンドタブに対応し、15秒ごとの補助チェックも行います。一時停止時には表示を消しません。
- 複数タブでは再生中の通知元を優先し、同じ曲の連続報告を重複排除します。元のタブが閉じた場合、停止中に別タブが再生を開始した場合、90秒報告がない場合に通知元を移せます。複数の異なる曲を同時に流しても通知元は1つです。
- HTTP通信はService Workerで実行し、状態更新と送信処理をそれぞれ直列化します。送信先ごとに未処理曲、直前の送信、実行中の印、再試行、結果を保持します。1つの送信先の失敗でも、他の送信先の処理を続けます。ただし通信自体は直列なので、先行する通信のタイムアウトまで後続が待つことはあります。
- 未送信の曲は最新曲で上書きします。POST開始後は取り消さず、完了後に最新曲を処理します。OFF保存時は未送信分を破棄します。
- 設定・認証情報・復旧情報は `chrome.storage.local` に保存します。30秒間隔のalarmとWorker起動で未処理分を復旧します。1リクエストは8秒でタイムアウトし、結果が確定している失敗は30秒以上間隔をあけて最大3回試行します。
- storageは `TRUSTED_CONTEXTS` に制限し、Content Scriptには認証情報を渡しません。設定操作は拡張のOptions Pageからだけ受け付けます。

## 権限

`storage` と `alarms` のみを使用します。静的Content Scriptは `https://music.youtube.com/*` で実行します。任意の送信先を設定できるよう `optional_host_permissions` にHTTPとHTTPSを宣言し、ユーザーが保存・テストしたホストだけの権限を取得します。インストール時に全Webサイトへの通信権限を取得しません。`tabs`、`scripting`、`webRequest` などは不要です。

## 動作確認

1. 汎用WebhookとLaMetricを追加し、それぞれのURL、認証、JSONを設定します。
2. プレビューで形式を確認し、接続テストを行います。汎用Webhookでは受信側のログも確認します。
3. 全体と各送信先をONにして「すべて保存」を押します。
4. YouTube Musicの曲を再生し、ラズパイ等の受信側でJSONを、LaMetricで表示を確認します。
5. 次の曲への切替と連続スキップを試し、最新曲が反映されることを確認します。
6. 別タブを前面にした状態、YouTube Music内でページ移動した状態でも確認します。
7. YouTube Musicを複数タブで開き、重複送信がないことを確認します。
8. 片方の受信側を停止し、エラーになってももう片方が受信できることを確認します。
9. 全体または送信先をOFFにして保存し、その後の新規通知が止まることを確認します。
10. `chrome://extensions` でWorkerが非稼働になるまでDevToolsを閉じて待ち、その後の曲変更でも送信できることを確認します。

設定画面の「送信状況」に送信先ごとの結果とエラーを表示します。認証・接続を修正した後に保存し直すと、最新の観測曲を再送します。

## 制約

- **受信側のPOSTとローカル状態保存は原子的に確定できません。** POST直後のWorker強制終了・通信切断・タイムアウトでは、配信結果が不明になる場合があります。この場合は自動再送を止め、次の曲変更を待ちます。受信済みの通知を取り消す処理は行いません。完全なexactly-once配信は保証しません。
- ChromeやPCの終了・スリープ中、タブの破棄・凍結中はDOMを監視できません。バックグラウンドのタイマー抑制で通知が遅れる場合があります。
- YouTube MusicのDOMは非公開仕様です。UIが変わった場合は `content.js` のセレクター調整が必要です。複数アーティストは先頭リンクの表示名を使用します。
- 認証情報は同期されませんが、ローカル保存は暗号化保管庫ではありません。HTTPは暗号化されないので信頼できるLANで使ってください。ブラウザーがローカルネットワーク接続の追加許可を求める場合は、意図した端末へのアクセスを許可してください。

| ファイル | 役割 |
| --- | --- |
| `manifest.json` | Manifest V3と権限 |
| `content.js` | DOM監視、安定確認、曲情報の報告 |

| `tests/` | Node標準機能だけの自動テスト |

Node.js 20以降で実行します。依存のインストールは不要です。

```sh
npm test
```

URL・認証・JSON展開、特殊文字、2xx/204、HTTPエラー・タイムアウト、POSTのみでのLaMetric送信、複数送信先の分離、競合、OFF、Worker再起動、重複排除、旧設定の移行、送信先削除時の無通信、DOM再生成をモックで検証します。
